# ARCHITECTURE.md

## 1. 개요

**한 줄 정의**
투자 전략이나 아이디어를 입력하면, AI가 다각적 관점(Bull/Bear/Risk)에서 근거를 검증하고
리스크를 분석하여 의사결정을 지원하는 Explainable AI 시스템.

**핵심 원칙**
> 판단을 대신하는 것이 아니라, 판단을 검증한다.

이 문서는 시스템 전체 구조의 소스 오브 트루스(source of truth)다. 코드는 이 문서를
구현한 결과물이어야 하며, 구조가 바뀌면 이 문서를 먼저 갱신한다.

---

## 2. 목표 / 비목표

### 목표
- 입력된 투자 전략에 대해 상충하는 관점(Bull/Bear/Risk)을 생성하고 서로 검증시킨다
- 근거의 신뢰도를 정량화한다 (Self-Consistency + CoVe 통과율 기반)
- 판단 과정(근거 → 반박 → 결론)을 사람이 추적 가능하도록 기록하고 설명한다
- 비용/지연을 고려해 LLM 호출을 계층적으로 라우팅한다
- 모든 도구 호출과 모델 호출을 감사 로그로 남긴다

### 비목표 (지금 단계에서 하지 않는 것)
- 실거래 연동, 자동 주문 실행
- 실시간 틱 데이터 처리 (백테스트는 일봉/월봉 수준으로 충분)
- 다국어 지원 (한국어 우선)
- 투자자문업 라이선스가 필요한 "확정적 투자 권유" 문구 생성 — 항상 참고용 정보로 프레이밍

## 3. 전체 구조

```
[React 클라이언트]
        │  (HTTPS / SSE)
        ▼
[API 게이트웨이 — FastAPI]
   인증 · 라우팅 · 입력 검증 · Rate limit
        │
        ▼
[에이전트 코어 — agent-core 패키지]
   ┌─────────────────────────────────────────┐
   │ 1. LLM 라우터        (모델 선택)         │
   │ 2. 멀티 에이전트 토론  (Bull/Bear/Risk)  │
   │ 3. ReAct 루프 + 도구 하네스              │
   │ 4. CoVe 검증 루프                        │
   │ 5. GraphRAG 인과 설명 생성               │
   │ 6. 신뢰도 점수 산출                      │
   └─────────────────────────────────────────┘
        │
        ▼
[데이터 / 인프라]
   Postgres(도메인 데이터, 감사로그) · Redis(캐시, 큐)
   외부: Claude API, 시장데이터 API(MCP 도구로 노출)
```

자세한 컴포넌트 다이어그램은 채팅에서 렌더링된 시각 자료(`ax_backend_architecture`,
`verification_pipeline_v2`) 참고. 이 문서는 그 다이어그램의 텍스트 사양이다.

## 4. 컴포넌트별 책임

### 4.1 API 게이트웨이 (FastAPI)
- 인증(JWT), 요청 검증(Pydantic), rate limiting
- 요청을 백그라운드 작업 큐(arq)에 등록하고 job_id 반환
- SSE로 에이전트의 Thought/Action/Observation 스트림을 클라이언트에 중계
- **agent-core에 대한 의존성만 가지며, 비즈니스 로직을 직접 갖지 않는다**

### 4.2 LLM 라우터
- 입력 1차 분류: 단순 케이스는 경량 모델(Haiku급)로 초안 생성
- Bull/Bear 간 결론 불일치도, Risk 점수가 임계치 초과 시 정밀 모델(Sonnet/Opus급)로 재라우팅
- 모든 라우팅 결정과 사유는 감사 로그에 기록
- 상세 기준: `agent-behavior.md#routing` 참조

### 4.3 멀티 에이전트 토론
- Bull / Bear / Risk 3개 페르소나가 독립적으로 초안 생성 후, 서로의 주장에 대해
  1회 이상 반박 라운드 진행
- Judge 역할은 별도 에이전트가 아니라 5번(신뢰도 점수 산출) 단계에서 규칙 기반 + 모델 기반 혼합으로 처리
- 각 에이전트의 도구 사용은 3번(ReAct 루프)에 위임

### 4.4 ReAct 루프 + 도구 하네스
- Thought → Action → Observation 반복, 최대 반복 횟수 하드 리밋
- 도구: `get_price_history`, `get_macro_indicator`, `run_backtest`, `search_news` 등
  (MCP 서버로 노출, `api-contract.md#mcp-tools` 참조)
- 도구 호출 입출력은 Pydantic 스키마로 강제 검증, 실패 시 재시도 후 폴백
- system/user/tool 결과 메시지는 역할별로 엄격히 분리 (프롬프트 인젝션 방어)

### 4.5 CoVe 검증 루프
- 정밀 모델로 재라우팅된 케이스에 한해 적용 (비용 통제)
- 각 핵심 주장에 대해 독립적인 검증 질문을 생성 → 별도로 답변 → 원 주장 수정
- 검증 통과율은 신뢰도 점수의 입력값으로 사용

### 4.6 GraphRAG 인과 설명
- CoVe로 검증된 근거를 (조건) → (중간 효과) → (결과) 형태의 노드-엣지로 저장
- 저장소는 초기엔 Postgres 인접 리스트 테이블로 시작, 필요 시 그래프 DB로 이관 가능하게 어댑터 계층 분리
- 이 그래프가 곧 Explainable AI의 "판단 과정" 산출물

### 4.7 신뢰도 점수
- 구성: Self-Consistency(동일 질문 N회 반복 시 결론 일치도) + CoVe 통과율 + 에이전트 간 합의도
- 각 구성 요소를 분해해서 보여줌으로써 "왜 이 점수인지" 설명 가능하게 함

### 4.8 데이터 / 인프라
- Postgres: 요청 이력, 에이전트 실행 로그, 감사 로그, GraphRAG 노드/엣지
- Redis: 시장데이터 캐시, arq 작업 큐, 세션 상태
- 모든 외부 API 호출: 재시도(exponential backoff), 타임아웃, 서킷브레이커

---

## 5. 보안 / 거버넌스

- 프롬프트 인젝션 방어: 외부 데이터(뉴스, 시장데이터)는 "데이터"로만 마킹되어 모델에 전달, 지시로 해석되지 않도록 시스템 프롬프트에서 명시
- 최종 리포트 출력 전 스키마 검증 + Human-in-the-loop 승인 게이트
- PII 및 민감 수치 마스킹
- 모든 LLM 호출·도구 호출·라우팅 결정을 감사 로그로 보존 (재현 가능성 확보)
- 결과물에는 항상 "참고용 정보이며 투자 조언이 아님" 문구 강제 포함

## 6. 비기능 요구사항

| 항목 | 목표 |
|---|---|
| 단일 요청 처리 시간 | 경량 라우팅 시 10초 이내, 정밀 라우팅 시 60초 이내 |
| 관측성 | 요청당 토큰 비용 / 지연 / 라우팅 경로 추적 가능 |
| 재현성 | 동일 입력 + 동일 시드로 감사 로그 기반 재현 가능 |
| 장애 격리 | 외부 API 장애 시 서킷브레이커로 전체 시스템 다운 방지 |

---

## 7. 기술 스택 요약

- Backend: FastAPI, async SQLAlchemy, Alembic, arq(Redis 큐)
- Agent Core: 순수 Python (프레임워크 독립), Pydantic 스키마 하네스
- Frontend: React, SSE 클라이언트
- 인프라: Postgres, Redis, Docker Compose
- 외부: Claude API, MCP 도구 서버, 시장데이터(FinanceDataReader / yfinance / FRED)
